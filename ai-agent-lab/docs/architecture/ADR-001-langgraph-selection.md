
# ADR-001: 选择 LangGraph 作为核心编排引擎

## 状态

**已接受** | 2024-01-15

## 背景

在设计企业级多智能体协作系统时，需要选择一个合适的框架来实现智能体编排。核心需求包括：

1. **复杂流程编排**：支持多智能体协作、循环执行、条件分支
2. **状态管理**：需要持久化对话状态，支持断点恢复
3. **可观测性**：支持执行流程可视化、调试和监控
4. **扩展性**：便于添加新的智能体和工具

## 决策选项

### 选项1：LangChain 原生 Agent

LangChain 提供了基础的 Agent 实现，包括：
- `AgentExecutor`：简单的 ReAct 风格 Agent
- `StructuredChatAgent`：结构化对话 Agent

**优势**：
- 与 LangChain 生态深度集成
- 上手简单，文档丰富

**劣势**：
- 状态管理有限，不支持检查点
- 循环和条件分支能力受限
- 可视化能力有限

### 选项2：LangGraph

LangGraph 是 LangChain 团队专门为复杂多智能体编排设计的框架：
- 基于状态机的流程编排
- 原生支持检查点和状态持久化
- 内置可视化能力

**优势**：
- 完整的状态机支持
- 原生检查点机制，支持断点恢复
- 强大的可视化能力（Mermaid 图）
- 支持循环和条件分支
- 与 LangChain 工具生态无缝集成

**劣势**：
- 相对较新，社区资源较少

### 选项3：自定义状态机

完全自主实现状态机和编排逻辑。

**优势**：
- 完全可控
- 可定制性强

**劣势**：
- 开发成本高
- 需要维护大量基础设施代码
- 缺乏可视化工具

## 决策结果

选择 **LangGraph** 作为核心编排引擎。

## 理由

| 评估维度 | LangChain Agent | LangGraph | 自定义实现 |
|---------|----------------|-----------|-----------|
| 状态管理 | 有限 | 完整 | 需自行实现 |
| 循环支持 | 受限 | 原生支持 | 需自行实现 |
| 检查点 | 无 | 原生支持 | 需自行实现 |
| 可视化 | 有限 | 完整 | 需自行实现 |
| 开发成本 | 低 | 中 | 高 |
| 社区支持 | 强 | 中等 | 无 |

## 影响

### 正面影响

1. **架构灵活性**：支持复杂的多智能体协作模式（监督者模式、委员会模式等）
2. **可维护性**：状态机可视化便于理解和调试
3. **生产就绪**：检查点机制支持故障恢复

### 负面影响

1. **学习曲线**：团队需要学习 LangGraph 的状态图概念
2. **资源有限**：相对较新的框架，社区资源较少

## 后续行动

1. 学习 LangGraph 核心概念（StateGraph、Node、Edge、Checkpointer）
2. 设计状态图结构，定义 AgentState
3. 实现监督者模式的多智能体协作流程
