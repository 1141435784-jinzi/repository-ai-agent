
# ADR-002: RAG 混合检索策略

## 状态

**已接受** | 2024-01-16

## 背景

RAG（检索增强生成）是本系统的核心能力，需要设计高效的检索策略。关键需求：

1. **语义理解**：能够理解用户查询的语义含义
2. **精确匹配**：能够精确匹配关键词（如产品型号、订单号）
3. **检索质量**：高召回率和精确率
4. **性能**：快速响应，支持大规模知识库

## 决策选项

### 选项1：纯向量检索

仅使用 Embedding 模型进行语义检索。

**优势**：
- 语义理解能力强
- 能够处理同义词、近义词

**劣势**：
- 对精确关键词匹配差
- 计算成本较高

### 选项2：纯 BM25 检索

仅使用传统信息检索算法。

**优势**：
- 关键词匹配精确
- 计算效率高

**劣势**：
- 不理解语义
- 无法处理同义词

### 选项3：混合检索（向量 + BM25）

结合向量语义检索和 BM25 关键词检索。

**优势**：
- 兼顾语义理解和精确匹配
- 使用 RRF（Reciprocal Rank Fusion）融合结果

**劣势**：
- 实现复杂度较高

### 选项4：混合检索 + Rerank

在混合检索基础上，使用 Cross-Encoder 进行重排序。

**优势**：
- 最高的检索质量
- 兼顾语义和关键词
- Rerank 精排提高结果相关性

**劣势**：
- 计算成本最高

## 决策结果

选择 **选项4：混合检索 + Rerank**

## 理由

| 评估维度 | 纯向量 | 纯 BM25 | 混合检索 | 混合+Rerank |
|---------|-------|---------|---------|-------------|
| 语义理解 | 优秀 | 差 | 良好 | 优秀 |
| 关键词匹配 | 差 | 优秀 | 良好 | 优秀 |
| 检索质量 | 良好 | 良好 | 优秀 | 优秀+ |
| 性能 | 中等 | 优秀 | 中等 | 中等- |
| 实现复杂度 | 低 | 低 | 中 | 高 |

## 技术方案

### 检索流程

```
用户查询
    │
    ├──▶ 向量检索（ChromaDB）───┐
    │                           │
    ├──▶ BM25 检索              │
    │                           ▼
    └────────────────▶ RRF 融合 ──▶ Cross-Encoder Rerank ──▶ 最终结果
```

### 组件选择

| 组件 | 技术 | 版本 | 理由 |
|------|------|------|------|
| Embedding | BAAI/bge-base-zh-v1.5 | latest | 中文效果优秀，开源免费 |
| 向量DB | ChromaDB | latest | 轻量级，易于部署 |
| Rerank | BAAI/bge-reranker-v2-m3 | latest | Cross-Encoder，中文效果优秀 |
| BM25 | langchain_community.BM25Retriever | latest | 与 LangChain 集成 |

### 参数配置

| 参数 | 值 | 说明 |
|------|-----|------|
| CHUNK_SIZE | 500 | 文本分块大小（字符） |
| CHUNK_OVERLAP | 80 | 块重叠大小 |
| TOP_K | 5 | 初步检索返回数量 |
| RERANK_TOP_N | 3 | Rerank 后保留数量 |
| VECTOR_WEIGHT | 0.6 | 向量检索权重 |
| BM25_WEIGHT | 0.4 | BM25 检索权重 |

## 影响

### 正面影响

1. **检索质量提升**：混合策略兼顾语义和关键词
2. **用户体验**：更准确的回答，减少幻觉
3. **可扩展性**：支持大规模知识库

### 负面影响

1. **资源消耗**：Rerank 模型需要额外的计算资源
2. **延迟**：多阶段检索增加响应时间
