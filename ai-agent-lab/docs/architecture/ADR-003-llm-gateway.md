
# ADR-003: LLM Gateway 多模型路由设计

## 状态

**已接受** | 2024-01-17

## 背景

企业级应用需要保证 LLM 服务的高可用性和成本可控。核心需求：

1. **容灾降级**：主模型失败时自动切换备用模型
2. **成本优化**：根据任务类型选择性价比最高的模型
3. **多语言支持**：支持中英文等多语言场景
4. **可观测性**：记录调用统计、成本、性能指标

## 决策选项

### 选项1：直接调用单一模型

每个请求直接调用配置的模型。

**优势**：
- 实现简单
- 性能开销低

**劣势**：
- 单点故障风险
- 无法优化成本

### 选项2：静态路由（按优先级）

配置多个模型，按优先级顺序调用，失败时降级。

**优势**：
- 支持容灾降级
- 实现相对简单

**劣势**：
- 无法根据任务类型选择模型
- 固定优先级，不够灵活

### 选项3：智能路由（动态选择）

根据任务特征（语言、复杂度）动态选择最优模型。

**优势**：
- 支持容灾降级
- 智能选择最优模型
- 成本优化

**劣势**：
- 实现复杂度较高
- 需要额外的决策逻辑

## 决策结果

选择 **选项3：智能路由**

## 技术方案

### Gateway 架构

```
                    ┌─────────────────┐
                    │   LLM Gateway   │
                    └────────┬────────┘
                             │
        ┌────────────────────┼────────────────────┐
        ▼                    ▼                    ▼
┌───────────────┐    ┌───────────────┐    ┌───────────────┐
│  DeepSeek     │    │   Zhipu AI    │    │   Ollama      │
│ (主模型)      │    │  (备用)       │    │  (本地)       │
└───────────────┘    └───────────────┘    └───────────────┘
```

### 路由策略

| 特征 | 选择策略 | 示例 |
|------|---------|------|
| 语言检测 | 中文→Qwen，英文→Llama | "你好"→Qwen，"Hello"→Llama |
| 任务类型 | 简单对话→轻量模型，复杂推理→强模型 | 闲聊→glm-4-flash，代码→deepseek-chat |
| 降级策略 | 主模型失败→备用模型→本地模型 | DeepSeek 503→Zhipu→Ollama |

### 模型配置

| Provider | 模型 | 优先级 | 适用场景 |
|----------|------|--------|----------|
| DeepSeek | deepseek-chat | 0 | 默认主模型 |
| Zhipu | glm-4-flash | 1 | 备用，成本低 |
| Ollama | qwen2.5:3b | 2 | 本地部署，隐私敏感场景 |
| Ollama | llama3.2:3b | 2 | 英文场景 |

### 调用统计

记录每次调用的：
- Provider 和模型名称
- 调用耗时
- Token 使用量
- 成本估算
- 成功/失败状态

## 影响

### 正面影响

1. **高可用性**：多模型容灾，服务不中断
2. **成本优化**：智能选择性价比最高的模型
3. **可观测性**：完整的调用统计和监控

### 负面影响

1. **复杂度**：增加了 Gateway 层的实现复杂度
2. **延迟**：路由决策增加少量开销

## 后续行动

1. 实现 LLM Gateway 核心模块
2. 实现智能路由策略（语言检测、任务分类）
3. 集成 Prometheus 指标监控
4. 实现成本统计和告警
