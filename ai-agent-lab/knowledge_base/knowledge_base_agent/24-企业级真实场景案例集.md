## 案例一：智能客服系统（电商行业）

### 业务背景

某电商平台日均客服咨询量 5 万+，人工客服成本高、响应慢。需要一个 AI 客服 Agent 处理 80% 的常见问题，复杂问题转人工。

### 技术架构

```
用户 → 意图识别 Agent → 路由
                         ├→ 订单查询 Agent（查订单、物流）
                         ├→ 退换货 Agent（处理退换货流程）
                         ├→ 产品咨询 Agent（RAG 检索产品知识库）
                         ├→ 投诉处理 Agent（情绪安抚 + 工单创建）
                         └→ 转人工（复杂/敏感问题）
```

### 核心实现

```python
from typing import TypedDict, Annotated, Literal
from operator import add
from langgraph.graph import StateGraph, START, END, MessagesState
from langchain.chat_models import init_chat_model
from langchain.agents import create_agent
from langchain_core.tools import tool
from pydantic import BaseModel, Field

# ===== 状态定义 =====
class CustomerServiceState(TypedDict):
    messages: Annotated[list, add]
    customer_id: str
    intent: str | None
    sentiment: str | None
    resolved: bool

# ===== 工具定义 =====
@tool
def query_order(order_id: str) -> str:
    """查询订单详情，包括状态、金额、物流信息"""
    return order_service.get_detail(order_id)

@tool
def track_logistics(order_id: str) -> str:
    """查询物流轨迹"""
    return logistics_service.track(order_id)

@tool
def create_return_request(order_id: str, reason: str) -> str:
    """创建退货申请"""
    return return_service.create(order_id, reason)

@tool
def search_product_faq(query: str) -> str:
    """搜索产品知识库"""
    docs = product_retriever.invoke(query)
    return "\n".join(doc.page_content for doc in docs[:3])

@tool
def create_complaint_ticket(customer_id: str, content: str, priority: str) -> str:
    """创建投诉工单"""
    return ticket_service.create(customer_id, content, priority)

# ===== 意图识别 =====
class IntentResult(BaseModel):
    intent: Literal["order_query", "return", "product_faq", "complaint", "human"]
    sentiment: Literal["positive", "neutral", "negative", "angry"]
    confidence: float

def detect_intent(state: CustomerServiceState) -> dict:
    llm = init_chat_model("openai:gpt-4o")
    result = llm.with_structured_output(IntentResult).invoke([
        {"role": "system", "content": "分析用户意图和情绪"},
        *state["messages"]
    ])
    return {"intent": result.intent, "sentiment": result.sentiment}

# ===== 路由 =====
def route_by_intent(state: CustomerServiceState) -> str:
    # 愤怒情绪直接转投诉处理
    if state["sentiment"] == "angry":
        return "complaint_handler"
    return state["intent"] or "human"

# ===== 各专业 Agent =====
def order_query_handler(state: CustomerServiceState) -> dict:
    agent = create_agent(
        model=init_chat_model("openai:gpt-4o"),
        tools=[query_order, track_logistics],
        prompt="你是订单查询专家。帮用户查询订单状态和物流信息。语气友好专业。"
    )
    result = agent.invoke({"messages": state["messages"]})
    return {"messages": result["messages"][-1:], "resolved": True}

def return_handler(state: CustomerServiceState) -> dict:
    agent = create_agent(
        model=init_chat_model("openai:gpt-4o"),
        tools=[query_order, create_return_request],
        prompt="""你是退换货处理专家。流程：
1. 先查询订单确认存在
2. 了解退货原因
3. 确认符合退货条件（7天内、未使用等）
4. 创建退货申请
5. 告知用户后续流程"""
    )
    result = agent.invoke({"messages": state["messages"]})
    return {"messages": result["messages"][-1:], "resolved": True}

# ===== 构建图 =====
graph = StateGraph(CustomerServiceState)
graph.add_node("detect_intent", detect_intent)
graph.add_node("order_query", order_query_handler)
graph.add_node("return", return_handler)
graph.add_node("product_faq", product_faq_handler)
graph.add_node("complaint_handler", complaint_handler)
graph.add_node("human_transfer", human_transfer)

graph.add_edge(START, "detect_intent")
graph.add_conditional_edges("detect_intent", route_by_intent, {
    "order_query": "order_query",
    "return": "return",
    "product_faq": "product_faq",
    "complaint": "complaint_handler",
    "human": "human_transfer",
})

for node in ["order_query", "return", "product_faq", "complaint_handler", "human_transfer"]:
    graph.add_edge(node, END)

customer_service_app = graph.compile(checkpointer=PostgresSaver.from_conn_string(DB_URL))
```

### 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 架构模式 | Supervisor（意图路由） | 客服场景意图明确，路由清晰 |
| 记忆方案 | Checkpoint + 长期记忆 | 需要跨会话延续 + 客户画像 |
| RAG | 混合检索 + Rerank | 产品知识库需要高精度检索 |
| 人工介入 | 情绪检测 + 复杂度判断 | 愤怒用户和复杂问题转人工 |

## 案例二：金融风控审批 Agent（金融行业）

### 业务背景

某银行的贷款审批流程：收到申请 → 征信查询 → 收入验证 → 风险评估 → 审批决策。传统流程需要 3-5 个工作日，Agent 可以将标准案件缩短到分钟级。

### 核心流程

```
申请提交 → 资料完整性检查 → 征信查询 → 收入验证
                                          ↓
              ← 人工复审 ← 风险评估 ← 反欺诈检查
              ↓
         审批决策（自动/人工）
```

### 关键代码

```python
class LoanApprovalState(TypedDict):
    application_id: str
    applicant_info: dict
    credit_report: dict | None
    income_verification: dict | None
    fraud_check: dict | None
    risk_score: float | None
    decision: str | None
    requires_human_review: bool
    messages: Annotated[list, add]

@tool
def query_credit_bureau(id_number: str) -> str:
    """查询央行征信报告"""
    return credit_api.query(id_number)

@tool
def verify_income(applicant_id: str) -> str:
    """验证收入证明（对接税务系统）"""
    return tax_api.verify_income(applicant_id)

@tool
def check_fraud_risk(applicant_id: str) -> str:
    """反欺诈检查（对接风控模型）"""
    return fraud_model.predict(applicant_id)

def risk_assessment(state: LoanApprovalState) -> dict:
    """AI 风险评估"""
    prompt = f"""基于以下信息进行贷款风险评估：

征信报告：{state['credit_report']}
收入验证：{state['income_verification']}
反欺诈结果：{state['fraud_check']}

请评估：
1. 风险等级（低/中/高）
2. 建议额度
3. 建议利率
4. 关键风险点
5. 是否需要人工复审"""

    result = llm.with_structured_output(RiskAssessment).invoke(prompt)

    # 高风险或大额贷款必须人工审批
    needs_human = (
        result.risk_level == "高"
        or state["applicant_info"].get("amount", 0) > 500000
    )

    return {
        "risk_score": result.risk_score,
        "requires_human_review": needs_human,
        "messages": [AIMessage(content=f"风险评分: {result.risk_score}, 需要人工: {needs_human}")]
    }

# Human-in-the-Loop：高风险案件暂停等待人工审批
app = graph.compile(
    checkpointer=checkpointer,
    interrupt_before=["human_review"]  # 在人工审核节点前暂停
)
```

## 案例三：ERP 智能数据分析助手（制造业）

### 业务背景

制造企业的管理层需要频繁查看各种经营数据：销售额、库存、产能利用率等。传统方式是让 IT 部门出报表，周期长。Agent 可以让管理层用自然语言直接查询数据。

### 核心能力

```python
@tool
def query_sales_data(
    start_date: str,
    end_date: str,
    dimension: str = "product",
    region: str | None = None,
) -> str:
    """查询销售数据。

    Args:
        start_date: 开始日期，格式 YYYY-MM-DD
        end_date: 结束日期，格式 YYYY-MM-DD
        dimension: 分析维度：product(产品)/region(区域)/channel(渠道)/salesperson(销售员)
        region: 可选，指定区域筛选
    """
    sql = build_sales_query(start_date, end_date, dimension, region)
    result = db.execute(sql)
    return format_as_table(result)

@tool
def query_inventory(sku: str | None = None, warehouse: str | None = None) -> str:
    """查询库存数据"""
    return inventory_service.query(sku, warehouse)

@tool
def generate_chart(data: str, chart_type: str, title: str) -> str:
    """生成图表。chart_type: bar/line/pie"""
    chart_url = chart_service.create(data, chart_type, title)
    return f"图表已生成: {chart_url}"

@tool
def export_to_excel(data: str, filename: str) -> str:
    """将数据导出为 Excel 文件"""
    file_url = export_service.to_excel(data, filename)
    return f"Excel 已导出: {file_url}"

# Agent 配置
erp_agent = create_agent(
    model=init_chat_model("openai:gpt-4o"),
    tools=[query_sales_data, query_inventory, generate_chart, export_to_excel],
    prompt="""你是企业数据分析助手。用户是公司管理层，用自然语言提问。

你的职责：
1. 理解用户的数据需求
2. 查询相关数据
3. 进行分析和洞察
```

## 案例四：供应链异常检测与响应（零售行业）

### 业务背景

大型零售企业有数千个 SKU、数十个仓库。供应链中的异常（缺货、滞销、物流延迟）需要快速发现和响应。

### Agent 架构

```python
class SupplyChainState(TypedDict):
    messages: Annotated[list, add]
    alerts: list[dict]              # 异常告警列表
    analysis_results: dict | None   # 分析结果
    action_plan: list[str]          # 行动计划
    executed_actions: Annotated[list, add]

def monitor_alerts(state: SupplyChainState) -> dict:
    """监控异常告警"""
    alerts = alert_service.get_active_alerts()
    return {"alerts": alerts}

def analyze_root_cause(state: SupplyChainState) -> dict:
    """分析异常根因"""
    prompt = f"""分析以下供应链异常的根本原因：

告警列表：
{json.dumps(state['alerts'], ensure_ascii=False, indent=2)}

请分析：
1. 每个异常的可能根因
2. 异常之间是否有关联
3. 影响范围评估
4. 紧急程度排序"""

    result = llm.invoke(prompt)
    return {"analysis_results": {"root_cause": result.content}}

def generate_action_plan(state: SupplyChainState) -> dict:
    """生成行动计划"""
    prompt = f"""基于以下分析结果，生成具体的行动计划：

分析结果：{state['analysis_results']}

要求：
1. 按紧急程度排序
2. 每个行动要具体可执行
3. 标注是否需要人工审批
4. 预估执行时间"""

    result = llm.invoke(prompt)
    return {"action_plan": result.content.split("\n")}

def execute_actions(state: SupplyChainState) -> dict:
    """执行自动化操作（低风险操作自动执行，高风险等待审批）"""
    executed = []
    for action in state["action_plan"]:
        if is_auto_executable(action):
            result = execute_action(action)
            executed.append(f"✅ {action}: {result}")
        else:
            executed.append(f"⏳ {action}: 等待人工审批")
    return {"executed_actions": executed}
```

## 案例五：智能合同审查 Agent（法务行业）

### 业务背景

企业法务部每天要审查大量合同，检查风险条款、合规性、与标准模板的偏差。Agent 可以自动完成初步审查，标注风险点，法务人员只需关注高风险条款。

### 核心实现

```python
@tool
def extract_contract_clauses(contract_text: str) -> str:
    """从合同文本中提取关键条款"""
    return clause_extractor.extract(contract_text)

@tool
def check_compliance(clauses: str, regulation: str = "default") -> str:
    """检查条款是否符合法规要求"""
    return compliance_checker.check(clauses, regulation)

@tool
def compare_with_template(clauses: str, template_name: str) -> str:
    """与标准合同模板对比，找出偏差"""
    return template_comparator.compare(clauses, template_name)

@tool
def search_legal_precedents(clause: str) -> str:
    """搜索相关法律判例"""
    return legal_rag.search(clause)

contract_review_agent = create_agent(
    model=init_chat_model("openai:gpt-4o"),
    tools=[extract_contract_clauses, check_compliance, compare_with_template, search_legal_precedents],
    prompt="""你是资深法务审查专家。审查合同时：

1. 提取所有关键条款（付款、违约、知识产权、保密、争议解决等）
2. 逐条检查合规性
3. 与标准模板对比，标注偏差
4. 对高风险条款给出修改建议
5. 搜索相关判例支撑你的建议

风险等级标注：
🔴 高风险：可能导致重大损失，必须修改
🟡 中风险：存在隐患，建议修改
🟢 低风险：轻微偏差，可接受

注意：你的审查结果仅供参考，最终决策由法务人员做出。"""
)
```

## 六、案例总结：技术选型对照表

| 案例 | 架构模式 | 记忆方案 | RAG | 人工介入 | 关键挑战 |
|------|----------|----------|-----|----------|----------|
| 智能客服 | Supervisor | Checkpoint+长期 | 产品知识库 | 情绪/复杂度触发 | 意图识别准确率 |
| 金融风控 | 顺序流水线 | Checkpoint | 法规知识库 | 高风险必须审批 | 合规性、可审计 |
| ERP 分析 | 单 Agent | 会话记忆 | 无 | 无 | 自然语言转 SQL |
| 供应链 | 顺序+条件 | 状态持久化 | 无 | 高风险操作 | 实时性、准确性 |
| 合同审查 | 单 Agent | 无 | 法律判例库 | 所有结果需确认 | 专业性、准确性 |
