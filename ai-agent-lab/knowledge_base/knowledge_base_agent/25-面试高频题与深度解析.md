> 最后的冲刺。50+ 道高频面试题，覆盖从基础概念到架构设计的全部范围。

## 一、基础概念题（10 题）

### Q1：什么是 AI Agent？和传统的 LLM 应用有什么区别？

**答题要点**：
- Agent = LLM + 工具调用 + 自主决策 + 记忆
- 传统 LLM 应用是"你问我答"，Agent 是"你给目标，我自己规划执行"
- 核心区别：Agent 有**自主决策能力**——能决定调用什么工具、按什么顺序执行
- 举例：传统应用是计算器（你输入公式它算），Agent 是会计（你说"帮我算税"，它自己知道该查什么数据、用什么公式）

### Q2：解释 ReAct 模式，为什么它是 Agent 的主流架构？

**答题要点**：
- ReAct = Reasoning（推理）+ Acting（行动）
- 核心循环：Thought → Action → Observation → Thought → ...
- 为什么有效：模拟人类"想-做-看-再想"的认知过程
- 对比纯推理（CoT）：CoT 只能想，不能做；ReAct 能想也能做
- 对比纯行动：没有推理的行动是盲目的，容易出错

### Q3：LangChain 和 LangGraph 的关系是什么？

**答题要点**：
- LangChain：提供模型集成、工具定义、Prompt 模板等**组件**
- LangGraph：提供状态图编排、持久化、人工介入等**编排能力**
- 关系：LangGraph 是 LangChain 生态的一部分，LangChain 1.x 的 create_agent 底层就是基于 LangGraph
- 类比：LangChain 是乐高积木块，LangGraph 是搭建说明书

### Q4：什么是 Function Calling / Tool Calling？

**答题要点**：
- LLM 根据用户需求，自主决定调用哪个外部函数、传什么参数
- 不是 LLM 直接执行函数，而是 LLM 输出"我想调用 X 函数，参数是 Y"，由运行时执行
- 关键：工具的 name + description + schema 决定了 LLM 能否正确调用
- 和 Plugin 的区别：Tool Calling 是模型原生能力，Plugin 是平台层的封装

### Q5：什么是 Hallucination（幻觉）？Agent 场景下怎么缓解？

**答题要点**：
- 幻觉：LLM 自信地生成不存在的信息
- Agent 场景的缓解手段：
  1. RAG：让 Agent 基于检索到的真实数据回答
  2. 工具验证：关键数据通过工具查询，而非 LLM 生成
  3. 自我反思：Agent 检查自己的回答是否有依据
  4. Prompt 约束："如果不确定，请说不知道"
  5. 输出验证：用 Pydantic 等验证输出格式和数据范围

## 二、LangChain / LangGraph 深度题（10 题）

### Q6：LangChain 1.x 的 create_agent 和 0.x 的 AgentExecutor 有什么区别？

**答题要点**：
- AgentExecutor（0.x）：黑盒循环，难以定制，不支持持久化
- create_agent（1.x）：基于 LangGraph，支持 Middleware、Checkpoint、Human-in-the-Loop
- 关键新特性：Middleware 机制——可以在 Agent 循环的任意阶段插入自定义逻辑
- 迁移建议：新项目直接用 create_agent，旧项目逐步迁移

### Q7：LangGraph 的 StateGraph 是什么？核心组成部分有哪些？

**答题要点**：
- StateGraph 是一个有向图，用于编排 Agent 的执行流程
- 四个核心组成：
  1. **State（状态）**：TypedDict，在所有节点间共享
  2. **Node（节点）**：Python 函数，执行具体操作
  3. **Edge（边）**：节点间的连接，定义执行顺序
  4. **Conditional Edge（条件边）**：根据状态动态路由
- 额外能力：Checkpoint（持久化）、interrupt（人工介入）、Subgraph（子图）

### Q8：什么是 Reducer？为什么 LangGraph 需要它？

**答题要点**：
- Reducer 定义了多个节点更新同一个状态字段时的合并策略
- 没有 Reducer：后写入的覆盖先写入的
- 有 Reducer（如 `Annotated[list, add]`）：追加而不是覆盖
- 为什么需要：Agent 的消息列表需要追加而非覆盖，否则会丢失历史消息
- 自定义 Reducer 示例：去重合并、取最大值、条件合并

### Q9：LangGraph 的 Checkpoint 机制是怎么工作的？

**答题要点**：
- 每次节点执行后，自动保存当前状态的快照
- 通过 thread_id 区分不同会话
- 支持多种存储后端：MemorySaver（开发）、SQLite（测试）、PostgreSQL（生产）
- 核心能力：故障恢复、Human-in-the-Loop、时间旅行（回溯历史状态）
- 实现原理：每个 Checkpoint 包含完整的状态快照 + 元数据（时间戳、节点名等）

### Q10：如何在 LangGraph 中实现 Human-in-the-Loop？

**答题要点**：
- `interrupt_before=["node_name"]`：在指定节点执行前暂停
- `interrupt_after=["node_name"]`：在指定节点执行后暂停
- 暂停后可以：
  - `invoke(None, config)`：继续执行
  - `update_state(config, new_values)`：修改状态后继续
- 典型场景：大额交易审批、敏感操作确认、AI 生成内容人工审核

## 三、RAG 深度题（8 题）

### Q11：RAG 的完整流程是什么？每个环节的关键点？

**答题要点**：
- 离线：文档加载 → 分块 → 向量化 → 存储
- 在线：查询改写 → 检索 → 重排序 → 生成
- 关键点：分块策略决定检索质量，Rerank 提升精确率，Prompt 约束减少幻觉

### Q12：文本分块的策略有哪些？如何选择？

**答题要点**：
- 递归字符分割：最通用，按分隔符层级切分
- Markdown 标题分割：适合结构化文档
- Token 分割：精确控制 Token 数
- 语义分割：按语义边界切分（高级）
- 选择原则：结构化文档用标题分割，通用文档用递归分割，chunk_size 通常 500-1000

### Q13：什么是混合检索？为什么需要它？

**答题要点**：
- 混合检索 = 向量检索（语义）+ BM25（关键词）
- 向量检索的局限：对精确关键词匹配差（如订单号、产品型号）
- BM25 的局限：不理解语义（"退货"和"退款"检索不到）
- 混合检索取长补短，通过权重融合两种结果

### Q14：什么是 Rerank？和 Embedding 检索有什么区别？

**答题要点**：
- Embedding 检索（Bi-Encoder）：query 和 doc 分别编码，计算余弦相似度。快但不够精确
- Rerank（Cross-Encoder）：query 和 doc 一起输入模型，精确打分。慢但更准确
- 实践：先用 Embedding 检索 Top 20，再用 Rerank 精排出 Top 5
- 常用模型：BAAI/bge-reranker-v2-m3

### Q15：RAG 中的幻觉问题怎么解决？

**答题要点**：
- Prompt 约束："只基于提供的参考资料回答，不确定就说不知道"
- 答案溯源：要求 Agent 引用具体来源
- 置信度评估：让 LLM 自评回答的置信度
- 检索质量保障：优化分块、Rerank、混合检索
- 兜底机制：低置信度时转人工

### Q16：如何评估 RAG 系统的效果？

**答题要点**：
- 检索评估：召回率、精确率、MRR（平均倒数排名）
- 生成评估：忠实度（是否基于检索内容）、相关性（是否切题）、完整性
- 端到端评估：用户满意度、任务完成率
- 工具：LangSmith 评估、RAGAS 框架

### Q17：知识库更新了，向量索引怎么同步？

**答题要点**：
- 增量更新：只处理新增/修改的文档
- 版本管理：每个文档记录版本号，更新时删旧增新
- 定时全量重建：适合小规模知识库
- 实时同步：监听文件变化，自动触发索引更新

### Q18：多语言 RAG 怎么做？

**答题要点**：
- 多语言 Embedding 模型（如 multilingual-e5-large）
- 查询翻译：将查询翻译为知识库语言后检索
- 混合策略：原始查询 + 翻译查询同时检索，合并结果

## 四、架构设计题（10 题）

### Q19：设计一个智能客服系统的 Agent 架构

**答题框架**：
1. 需求分析：日均咨询量、问题类型分布、SLA 要求
2. 架构选择：Supervisor 模式（意图路由 + 专业 Agent）
3. 核心组件：意图识别、情绪检测、RAG 知识库、工单系统集成
4. 记忆方案：Checkpoint（会话内）+ 长期记忆（客户画像）
5. 人工介入：情绪激动/复杂问题/VIP 客户自动转人工
6. 可观测性：LangSmith 追踪 + 满意度评估
7. 部署方案：FastAPI + PostgreSQL + Redis + Docker

### Q20：如何设计一个多 Agent 协作系统？

**答题框架**：
1. 确定 Agent 边界：每个 Agent 的职责和能力
2. 选择协作模式：Supervisor / Swarm / 层级
3. 通信机制：共享状态 vs 消息传递
4. 防止死循环：最大迭代次数 + 超时 + 状态记录
5. 错误处理：单个 Agent 失败不影响整体
6. 可观测性：追踪跨 Agent 的完整链路

### Q21：Agent 系统如何做到高可用？

**答题要点**：
- 多实例部署 + 负载均衡
- 模型降级链：主模型 → 备用模型 → 本地模型
- Checkpoint 持久化：故障后从断点恢复
- 优雅降级：Agent 不可用时返回友好提示
- 健康检查 + 自动重启
- 异步队列：削峰填谷

### Q22：如何控制 Agent 的成本？

**答题要点**：
- Token 预算：每次请求设置 Token 上限
- 迭代次数限制：防止 Agent 无限循环
- 模型分级：简单任务用小模型，复杂任务用大模型
- 缓存：相同问题直接返回缓存结果
- 消息裁剪：控制上下文长度
- 监控告警：Token 消耗异常时告警

### Q23：Agent 的安全防护怎么做？

**答题要点**：
- Prompt 注入防护：系统提示中声明安全规则 + 输入清洗
- 工具权限控制：基于角色的动态工具绑定
- 输出过滤：敏感信息脱敏
- 操作审计：所有工具调用记录日志
- 速率限制：防止滥用
- 人工审批：敏感操作必须人工确认

### Q24：如何设计 Agent 的记忆系统？

**答题要点**：
- 三层架构：工作记忆（消息列表）+ 短期记忆（Checkpoint）+ 长期记忆（向量 DB）
- 工作记忆管理：滑动窗口 / Token 限制 / 摘要压缩
- 长期记忆：对话结束后提取关键信息存入向量数据库
- 记忆召回：对话开始时，根据用户和话题召回相关记忆

### Q25：Agent 系统如何做灰度发布？

**答题要点**：
- Prompt 版本管理：不同版本的 Prompt 分配不同流量
- A/B 测试：新旧 Agent 同时运行，对比效果指标
- 金丝雀发布：先给 5% 用户使用新版本，观察指标
- 快速回滚：发现问题立即切回旧版本
- 评估指标：正确率、满意度、延迟、成本

### Q26：如何处理 Agent 的长时间运行任务？

**答题要点**：
- LangGraph 的 Checkpoint 机制：自动保存进度
- 异步执行：不阻塞用户请求
- 进度通知：通过 WebSocket 或轮询告知用户进度
- 超时处理：设置最大执行时间
- 断点恢复：服务重启后从最后的 Checkpoint 恢复

### Q27：如何测试 Agent？

**答题要点**：
- 单元测试：测试单个工具函数
- 集成测试：测试 Agent 的完整流程（用 mock 的 LLM）
- 评估测试：用评估数据集测试 Agent 的回答质量
- 回归测试：每次修改后确保不影响已有功能
- 压力测试：测试并发性能
- 红队测试：测试安全防护（Prompt 注入等）

### Q28：Agent 和微服务架构如何结合？

**答题要点**：
- 每个 Agent 可以是一个独立的微服务
- 通过 API Gateway 统一入口
- Agent 之间通过消息队列（如 Kafka）异步通信
- 共享状态通过数据库（PostgreSQL）或缓存（Redis）
- 每个 Agent 独立部署、独立扩缩容

## 六、开放性讨论题（5 题）

### Q36：Agent 会取代传统的 RPA 吗？

**讨论方向**：
- RPA：基于规则，确定性高，适合固定流程
- Agent：基于 LLM，灵活性高，适合开放性任务
- 趋势：Agent + RPA 结合——Agent 做决策，RPA 做执行
- 短期内不会取代，而是互补

### Q37：Agent 的可靠性能达到生产要求吗？

**讨论方向**：
- 当前挑战：幻觉、不确定性、延迟
- 解决方案：Human-in-the-Loop、输出验证、降级策略
- 适用场景：辅助决策（人+AI）比完全自主更可靠
- 趋势：随着模型能力提升，可靠性持续改善

### Q38：如何评估一个 Agent 项目的 ROI？

**讨论方向**：
- 成本：模型 API 费用 + 开发维护成本 + 基础设施成本
- 收益：人力节省 + 效率提升 + 用户体验改善
- 指标：自动化率、平均处理时间、用户满意度、错误率
- 关键：先做 MVP 验证，再逐步扩大

### Q39：Agent 的伦理和合规问题有哪些？

**讨论方向**：
- 数据隐私：Agent 处理的数据是否合规
- 决策透明：Agent 的决策过程是否可解释
- 责任归属：Agent 做出错误决策，谁负责
- 偏见问题：LLM 的偏见是否会影响 Agent 的决策
- 合规要求：金融、医疗等行业的特殊合规要求

### Q40：未来 3 年 Agent 技术的发展趋势？

**讨论方向**：
- 多模态 Agent：文本+图片+语音+视频
- 自主性提升：从辅助决策到自主执行
- Agent 即服务：Agent as a Service（AaaS）
- 标准化：Agent 通信协议、评估标准
- 垂直行业深耕：金融、医疗、法律、制造等专业 Agent

## 七、编码题（10 题）

### Q41：用 LangGraph 实现一个带工具调用的 ReAct Agent

```python
# 参考答案框架
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.prebuilt import ToolNode

def build_react_agent(llm, tools):
    tool_node = ToolNode(tools)

    def agent(state: MessagesState):
        return {"messages": [llm.bind_tools(tools).invoke(state["messages"])]}

    def should_continue(state: MessagesState):
        if state["messages"][-1].tool_calls:
            return "tools"
        return "end"

    graph = StateGraph(MessagesState)
    graph.add_node("agent", agent)
    graph.add_node("tools", tool_node)
    graph.add_edge(START, "agent")
    graph.add_conditional_edges("agent", should_continue, {"tools": "tools", "end": END})
    graph.add_edge("tools", "agent")
    return graph.compile()
```

## 八、面试技巧

1. **先说架构，再说细节**：面试官想看你的全局视野，不是让你背 API
2. **用真实场景举例**：每个技术点都要能关联到企业场景
3. **承认局限性**：Agent 不是万能的，知道什么时候不该用 Agent 也很重要
4. **展示权衡思维**：技术选型没有最优解，只有最适合的。说清楚为什么选 A 不选 B
5. **代码要能跑**：编码题不需要完美，但要能体现核心思路，且逻辑正确
