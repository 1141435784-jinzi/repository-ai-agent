# 成本管控与计费

> 适用场景：使用 LLM API 的生产 Agent 系统，需要控制和追踪 token 消耗成本
> 最后更新：2026 年 4 月

---

## 一、为什么成本管控是生产必需

LLM API 按 token 计费，成本很容易失控：

- 一次复杂的 Agent 调用可能涉及多轮 LLM 交互（意图判断 + RAG + 工具调用 + 最终回答）
- 每轮都消耗 token，对话越长上下文越大，成本指数增长
- 一个恶意用户或 bug 可能在短时间内消耗大量 token

**现实案例**：某企业 Agent 上线后，因为没有成本控制，一个用户通过超长对话在一天内消耗了相当于一个月预算的 token 费用。

## 二、Token 成本基础知识

### 2.1 主流模型定价（参考，实际以官方为准）

| 模型 | 输入价格（/百万 token） | 输出价格（/百万 token） |
|---|---|---|
| GPT-4o | ~$2.5 | ~$10 |
| GPT-4o-mini | ~$0.15 | ~$0.6 |
| GPT-4 | ~$30 | ~$60 |
| Claude 3.5 Sonnet | ~$3 | ~$15 |
| 本地模型 | 硬件成本（固定） | 硬件成本（固定） |

### 2.2 一次 Agent 调用的成本构成

```
用户提问："帮我查一下订单 ORD-001 的状态"

第 1 次 LLM 调用：意图判断
  输入：System Prompt(500) + 用户消息(20) = 520 tokens
  输出：意图结果(10) = 10 tokens

第 2 次 LLM 调用：Agent 思考 + 工具调用决策
  输入：System Prompt(500) + 对话历史(530) + RAG 上下文(800) = 1830 tokens
  输出：工具调用指令(50) = 50 tokens

第 3 次 LLM 调用：生成最终回答
  输入：System Prompt(500) + 对话历史(1880) + 工具结果(200) = 2580 tokens
  输出：最终回答(150) = 150 tokens

总计：输入 ~4930 tokens + 输出 ~210 tokens
```

关键发现：**输入 token 远多于输出 token**，而且随着对话轮次增加，输入 token 会快速膨胀（因为对话历史越来越长）。

## 三、成本追踪实现

### 3.1 使用 LangChain Callback 追踪

```python
from langchain_core.callbacks import BaseCallbackHandler
from langchain_community.callbacks import get_openai_callback

# 方式一：OpenAI 专用回调
with get_openai_callback() as cb:
    result = agent.invoke({"messages": [("user", "你好")]}, config)
    print(f"总 token: {cb.total_tokens}")
    print(f"总成本: ${cb.total_cost:.4f}")

# 方式二：自定义回调（支持所有模型）
class CostTracker(BaseCallbackHandler):
    def __init__(self):
        self.total_input_tokens = 0
        self.total_output_tokens = 0

    def on_llm_end(self, response, **kwargs):
        usage = response.llm_output.get("token_usage", {})
        self.total_input_tokens += usage.get("prompt_tokens", 0)
        self.total_output_tokens += usage.get("completion_tokens", 0)

    @property
    def total_cost(self) -> float:
        # 按实际模型定价计算
        input_cost = self.total_input_tokens * 2.5 / 1_000_000
        output_cost = self.total_output_tokens * 10 / 1_000_000
        return input_cost + output_cost
```

### 3.2 按租户/用户归属成本

```python
import logging
from datetime import datetime

cost_logger = logging.getLogger("cost")

class TenantCostTracker(BaseCallbackHandler):
    """按租户追踪成本"""

    def __init__(self, tenant_id: str, user_id: str):
        self.tenant_id = tenant_id
        self.user_id = user_id
        self.session_tokens = {"input": 0, "output": 0}

    def on_llm_end(self, response, **kwargs):
        usage = response.llm_output.get("token_usage", {})
        input_tokens = usage.get("prompt_tokens", 0)
        output_tokens = usage.get("completion_tokens", 0)

        self.session_tokens["input"] += input_tokens
        self.session_tokens["output"] += output_tokens

        # 记录到日志/数据库
        cost_logger.info(
            f"TENANT={self.tenant_id} USER={self.user_id} "
            f"INPUT={input_tokens} OUTPUT={output_tokens} "
            f"TIME={datetime.now().isoformat()}"
        )

    def get_session_cost(self) -> float:
        return (
            self.session_tokens["input"] * 2.5 / 1_000_000
            + self.session_tokens["output"] * 10 / 1_000_000
        )
```

## 五、降本策略

### 5.1 模型路由（最有效的降本手段）

```python
def route_to_model(message: str, intent: str) -> str:
    """根据任务复杂度选择模型"""
    # 简单问候/闲聊 → 最便宜的模型
    if intent == "greeting":
        return "gpt-4o-mini"

    # RAG 问答 → 中等模型
    if intent == "rag":
        return "gpt-4o-mini"  # RAG 有上下文辅助，不需要最强模型

    # 复杂推理/多步骤任务 → 高端模型
    if intent == "complex_reasoning":
        return "gpt-4o"

    return "gpt-4o-mini"  # 默认用便宜的
```

**效果**：大部分请求（70-80%）可以用便宜模型处理，整体成本降低 50-70%。

### 5.2 上下文压缩

对话越长，输入 token 越多。定期压缩对话历史：

```python
from langchain_core.messages import trim_messages

# 只保留最近 N 条消息
trimmed = trim_messages(
    messages,
    max_tokens=2000,
    strategy="last",
    token_counter=len,  # 简单用字符数估算
)

# 或者：摘要旧消息
def compress_history(messages, max_messages=10):
    if len(messages) <= max_messages:
        return messages

    old_messages = messages[:-max_messages]
    recent_messages = messages[-max_messages:]

    # 用便宜模型生成摘要
    summary = cheap_llm.invoke(
        f"请用一段话总结以下对话的关键信息：\n{format_messages(old_messages)}"
    )

    return [SystemMessage(content=f"[历史摘要] {summary.content}")] + recent_messages
```

### 5.4 RAG 上下文精简

检索到的文档不要全部塞给 LLM，只保留最相关的部分：

```python
# 控制送入 LLM 的上下文长度
MAX_CONTEXT_TOKENS = 1500

def trim_context(documents: list, max_tokens: int = MAX_CONTEXT_TOKENS) -> str:
    context = ""
    for doc in documents:
        if len(context) + len(doc.page_content) > max_tokens:
            break
        context += doc.page_content + "\n\n"
    return context
```
