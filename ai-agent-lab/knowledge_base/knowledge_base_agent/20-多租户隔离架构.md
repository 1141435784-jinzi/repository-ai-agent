# 多租户隔离架构

> 适用场景：企业 SaaS 型 Agent 服务，需要为不同客户/部门提供隔离的 Agent 能力
> 最后更新：2026 年 4 月

---

## 一、什么是多租户

多租户（Multi-Tenancy）是指一套系统同时服务多个客户（租户），每个租户的数据、配置、行为互不干扰。

**现实例子**：一栋写字楼里有多家公司，共享电梯和大堂（基础设施），但每家公司有独立的办公室（数据隔离）、独立的门禁卡（权限控制）、独立的电费账单（成本计量）。

**Agent 场景下的多租户需求**：
- 租户 A 的知识库不能被租户 B 检索到
- 租户 A 的对话历史不能被租户 B 看到
- 租户 A 的 token 消耗不能算到租户 B 头上
- 不同租户可以有不同的模型配置、Prompt 模板、工具权限

## 二、需要隔离的四个层面

### 2.1 对话隔离（Checkpoint / Memory）

最基本的隔离——不同租户的对话历史必须完全分开。

```python
# 方案一：thread_id 中嵌入租户标识
config = {
    "configurable": {
        "thread_id": f"tenant_{tenant_id}_user_{user_id}_session_{session_id}"
    }
}

# 方案二：每个租户使用独立的 Checkpointer 实例（更强隔离）
tenant_checkpointers = {}

def get_checkpointer(tenant_id: str):
    if tenant_id not in tenant_checkpointers:
        # 每个租户一个独立的数据库/表
        tenant_checkpointers[tenant_id] = SqliteSaver.from_conn_string(
            f"checkpoints_{tenant_id}.db"
        )
    return tenant_checkpointers[tenant_id]
```

| 方案 | 隔离强度 | 复杂度 | 适用场景 |
|---|---|---|---|
| thread_id 前缀 | 中（逻辑隔离） | 低 | 内部多部门 |
| 独立数据库/表 | 高（物理隔离） | 中 | SaaS 产品 |
| 独立数据库实例 | 最高 | 高 | 金融/医疗等强合规 |

### 2.2 知识库隔离（RAG / 向量数据库）

不同租户的知识库文档必须隔离，防止跨租户信息泄露。

```python
# 方案一：同一个 Collection，用 metadata 过滤
vectorstore.similarity_search(
    query,
    k=5,
    filter={"tenant_id": tenant_id}  # 只检索当前租户的文档
)

# 方案二：每个租户独立的 Collection（推荐）
def get_vectorstore(tenant_id: str):
    return Chroma(
        collection_name=f"kb_{tenant_id}",
        embedding_function=embeddings,
        persist_directory=f"./chroma_db/{tenant_id}",
    )

# 方案三：每个租户独立的向量数据库实例（最强隔离）
```

**推荐方案二**：独立 Collection 在隔离性和管理成本之间取得平衡。方案一有过滤器被绕过的风险，方案三运维成本太高。

### 2.3 工具权限隔离

不同租户可能有不同的工具访问权限。

```python
# 租户工具配置
TENANT_TOOL_CONFIG = {
    "tenant_basic": {
        "allowed_tools": ["search_kb", "get_time", "calculator"],
        "model": "gpt-3.5-turbo",
        "max_iterations": 10,
    },
    "tenant_premium": {
        "allowed_tools": ["search_kb", "get_time", "calculator", "send_email", "create_ticket"],
        "model": "gpt-4",
        "max_iterations": 25,
    },
}

def build_tenant_agent(tenant_id: str):
    """为租户构建定制化 Agent"""
    config = TENANT_TOOL_CONFIG.get(tenant_id, TENANT_TOOL_CONFIG["tenant_basic"])

    available_tools = [t for t in ALL_TOOLS if t.name in config["allowed_tools"]]

    return create_agent(
        model=init_chat_model(f"openai:{config['model']}"),
        tools=available_tools,
        prompt=get_tenant_prompt(tenant_id),
        checkpointer=get_checkpointer(tenant_id),
        max_iterations=config["max_iterations"],
    )
```

### 2.4 配置隔离

不同租户可以有不同的 Prompt、模型、参数。

```python
# 租户配置存储（数据库或配置文件）
class TenantConfig:
    tenant_id: str
    system_prompt: str          # 定制化 Prompt
    model_name: str             # 使用的模型
    temperature: float          # 生成温度
    max_tokens: int             # 最大 token 数
    knowledge_base_path: str    # 知识库路径
    allowed_tools: list[str]    # 允许的工具
    monthly_token_budget: int   # 月度 token 预算
```

## 三、多租户架构模式

### 3.1 共享 Agent + 运行时隔离（推荐起步方案）

```
所有租户共享同一个 Agent 图结构
    ↓
运行时通过 config 注入租户信息
    ↓
Checkpointer / VectorStore / Tools 按租户隔离
```

```python
@app.post("/chat")
async def chat(request: ChatRequest):
    tenant_id = request.tenant_id  # 从请求中获取租户 ID

    # 运行时注入租户配置
    config = {
        "configurable": {
            "thread_id": f"{tenant_id}_{request.thread_id}",
            "tenant_id": tenant_id,
        }
    }

    # 使用租户专属的 Agent
    agent = get_or_create_tenant_agent(tenant_id)
    result = await agent.ainvoke(
        {"messages": [("user", request.message)]},
        config
    )
    return result
```

**优点**：代码复用度高，运维简单
**缺点**：隔离强度依赖代码正确性，一个 bug 可能导致跨租户泄露

### 3.2 独立 Agent 实例（强隔离方案）

```
每个租户有独立的 Agent 实例
    ↓
独立的 Checkpointer + VectorStore + Tools
    ↓
通过路由层分发请求
```

**优点**：隔离最强，一个租户的问题不影响其他租户
**缺点**：资源消耗大，租户多时内存压力大

### 3.3 选型建议

| 场景 | 推荐方案 |
|---|---|
| 内部多部门使用 | 共享 Agent + thread_id 前缀 |
| SaaS 产品（中小租户） | 共享 Agent + 独立 Collection |
| 金融/医疗（强合规） | 独立 Agent 实例 + 独立数据库 |

## 四、租户身份认证

```python
from fastapi import Depends, HTTPException
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials
import jwt

security = HTTPBearer()

async def get_current_tenant(
    credentials: HTTPAuthorizationCredentials = Depends(security)
) -> str:
    """从 JWT Token 中提取租户 ID"""
    try:
        payload = jwt.decode(
            credentials.credentials,
            SECRET_KEY,
            algorithms=["HS256"]
        )
        tenant_id = payload.get("tenant_id")
        if not tenant_id:
            raise HTTPException(status_code=401, detail="无效的租户信息")
        return tenant_id
    except jwt.ExpiredSignatureError:
        raise HTTPException(status_code=401, detail="Token 已过期")

@app.post("/chat")
async def chat(request: ChatRequest, tenant_id: str = Depends(get_current_tenant)):
    # tenant_id 已经过验证，安全使用
    agent = get_or_create_tenant_agent(tenant_id)
```

## 五、多租户测试要点

| 测试项 | 验证内容 |
|---|---|
| 对话隔离 | 租户 A 的对话历史在租户 B 的会话中不可见 |
| 知识库隔离 | 租户 A 的文档不会出现在租户 B 的检索结果中 |
| 权限隔离 | 租户 A 无法调用未授权的工具 |
| 成本隔离 | 租户 A 的 token 消耗正确归属 |
| 故障隔离 | 租户 A 的异常不影响租户 B 的服务 |
