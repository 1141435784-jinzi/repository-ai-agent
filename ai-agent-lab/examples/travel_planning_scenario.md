
# 业务场景案例：旅行规划助手

## 场景概述

用户需要规划一次从北京到杭州的3天旅行，包含景点推荐、交通安排和美食推荐。系统需要协调多个领域专家（景点专家、交通专家、美食专家）共同完成这个复杂任务。

## 场景流程

### 初始请求
```
用户：我计划下周末从北京去杭州旅行，行程3天，请帮我规划一下。
```

### 执行流程

```
用户请求
    │
    ▼
┌──────────────┐
│ Supervisor   │  分析请求，判断需要多个专家协作
└──────┬───────┘
       │
       ▼ 路由到 plan_agent
┌──────────────┐
│  Plan Agent  │  制定旅行计划框架
└──────┬───────┘
       │
       ├─▶ sights_agent (推荐景点)
       ├─▶ transport_agent (规划交通)
       └─▶ food_agent (推荐美食)
       │
       ▼
┌──────────────┐
│ Supervisor   │  汇总各专家结果，判断是否需要补充信息
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  Summary     │  生成最终旅行方案
└──────────────┘
```

### 专家协作详情

#### 1. Plan Agent（计划专家）
```
输入：北京 → 杭州，3天行程
输出：
┌──────────┬─────────────────────────────┐
│ 日期     │ 行程安排                     │
├──────────┼─────────────────────────────┤
│ Day 1    │ 抵达杭州，西湖景区游览        │
│ Day 2    │ 灵隐寺 + 龙井茶园             │
│ Day 3    │ 宋城景区，返程                │
└──────────┴─────────────────────────────┘
```

#### 2. Sights Agent（景点专家）
```
输入：杭州，3天行程
输出：
- Day 1: 西湖（断桥、苏堤、雷峰塔）
- Day 2: 灵隐寺、龙井茶园
- Day 3: 宋城千古情演出
```

#### 3. Transport Agent（交通专家）
```
输入：北京→杭州，周末出行
输出：
- 去程：G171 北京南→杭州东 07:00-12:30
- 返程：G174 杭州东→北京南 16:00-21:30
- 市内：建议租用电动车或打车
```

#### 4. Food Agent（美食专家）
```
输入：杭州，3天行程
输出：
- Day 1 午餐：楼外楼（西湖醋鱼）
- Day 1 晚餐：知味观（小笼包）
- Day 2 午餐：龙井村农家菜（龙井虾仁）
- Day 2 晚餐：外婆家（杭帮菜）
- Day 3 午餐：奎元馆（片儿川）
```

## 技术亮点

### 1. 多专家协作
- Supervisor 模式实现任务拆解和结果汇总
- 各专家专注于自己的领域
- 支持并行执行多个专家

### 2. 工具调用
- 交通专家调用火车票查询工具
- 景点专家调用知识库检索（RAG）
- 美食专家调用本地知识库

### 3. 记忆机制
- 短期记忆：保存对话历史
- 长期记忆：记录用户偏好（如预算、口味）

### 4. 智能路由
- 根据任务类型选择合适的专家
- 支持动态添加新领域专家

## 扩展能力

### 添加新专家
只需在 `src/agents/` 目录下添加新的专家实现，在 `workflow.py` 中注册即可。

### 添加新工具
在 `src/tools/` 目录下实现工具，通过 MCP 协议集成。

### 扩展知识库
在 `data/knowledge/` 目录下添加 Markdown 文档，系统自动索引。
